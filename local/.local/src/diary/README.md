# 拾光日记

一个面向 Windows 与 Linux 的本地 Markdown 日记查看与编辑器。界面使用 Noto Sans，以紧凑时间轴串联 IM 聊天气泡式日记，支持实时自动保存、Markdown 阅读预览、全文搜索、数学公式和年月快速跳转。

## 启动

开发运行需要 Node.js 24 或更高版本。项目会安装 Electron 43（文本洞察使用 Electron 内置的 SQLite）。Linux Wayland 开发环境还需要 C 编译器和 `wayland-scanner`，`npm start` 会自动构建背景模糊桥接库：

```bash
npm install --include=dev
npm start
```

应用启动后，可通过“选择或创建目录”打开已有的 `Diary` 文件夹，也可直接在系统目录选择器中新建文件夹。Linux 使用 XDG Desktop Portal；Windows 会允许输入尚不存在的路径，并由应用完成目录创建。

设置面板可以可视化调整：

- 界面缩放比例（80%–150%）
- 深色模式
- 背景透明度（0%–100%，不会降低文字和图标的不透明度）
- 右侧年月快速导航的显示状态
- 密钥保护（Windows 使用系统凭据保护；Linux 可选择自动、KWallet 或 GNOME Libsecret）
- 高德 Web 服务 Key（用于地点候选搜索）
- 本地 Diary 目录

这些设置会持久化到 Electron 的平台应用数据目录中的 `config.json`，下次启动自动恢复；Linux 遵循 `$XDG_CONFIG_HOME`，Windows 使用当前用户的应用数据目录。

应用也会保存最近一次非最大化窗口的宽高和最大化状态；如果在最大化时关闭，下次仍以最大化打开，退出最大化后会恢复此前的窗口大小。

背景透明度只改变窗口结构背景的 alpha，不会对整个窗口设置 opacity，因此文字、图标和交互控件仍保持完整不透明。Windows 使用透明的无边框窗口和原生 Window Controls Overlay，保留系统最小化、最大化与关闭按钮。在 Windows 11 22H2 及更高版本上，透明度大于 0 时会通过 Electron 官方 `backgroundMaterial: 'acrylic'` 接口启用 DWM Desktop Acrylic 背景模糊；透明度回到 0 时会停用该材质。旧版 Windows 或系统关闭视觉效果时自然退化为仅透明，不加载第三方原生模块。

Linux Wayland 会在合成器公布模糊能力时，通过 [`ext-background-effect-v1`](https://wayland.app/protocols/ext-background-effect-v1) 为整个顶层窗口的透明区域请求背景模糊。模糊算法和强度由合成器决定；X11 或不支持该协议的 Wayland 合成器会自然退化为仅透明，不影响启动。由于 Electron 没有公开协议要求的 `wl_surface`，项目把兼容逻辑隔离在只随 Linux Wayland 启动的连接桥接库中，Windows 不会构建或加载它。可用 `SHIGUANG_DISABLE_WAYLAND_BLUR=1` 禁用桥接；排查协议协商时可设置 `SHIGUANG_WAYLAND_BLUR_DEBUG=1`。

左侧保留一个“选择年份”按钮，点击后可选择并跳到对应年份。右侧年月按钮会打开悬浮目录，不会改变或压缩时间轴宽度。

左侧“图库”按钮会切换到图片时间轴。图库按年月和日期展示所有 Markdown 图片缩略图，不显示日记气泡；点击图片后可滚轮缩放，放大后按住鼠标左键拖动查看，并使用左右按钮或方向键切换同一天的图片。首次打开图库时，应用会并发建立轻量图片索引，不会把所有日记正文保留在渲染进程内存中。

左侧“日历”按钮会打开按年份排列的月度热力图。实色日期表示已有日记，点击后回到时间轴并定位到对应记录；点击空白日期会直接创建该日期的日记并打开撰写窗口。日历顶部可以切换年份，也可以继续使用左侧年份选择器。

左侧“漫步”按钮会打开旧日回顾页面。“随机日记”会重新打乱整个日记索引；“那年今天”只收集日号相同且与今天相隔完整月份的历史日记。两个分类都使用可循环的横向堆叠卡片，可通过按钮、方向键、触控滑动或触控板横向滚动切换，正文仅在当前卡片附近按需载入。

左侧“洞察”按钮会在后台建立本地 SQLite 分析索引，提供记录覆盖率、正文词数、连续记录、星期分布、月度趋势、中文词频、同日词语关联，以及地点填写率、常去地点、坐标确认率和行政区分布。日期范围会同时作用于文字与地点统计；点击词语或地点可以回到全文搜索。文字分析只读取正文，地点统计只读取现有的 `地点:` 字段及独立地点数据库，不会改写日记或 Frontmatter；“重新建立分析索引”可以强制刷新全部结果。

已有确认坐标时，地点统计会提供“打开地点地图”。应用在弹窗中按当前洞察日期范围聚合相同坐标，显示高德标准地点名、日记中的原始称呼、行政区、地址、经纬度、记录次数及日期跨度；点击单个地点可继续在高德地图中打开。高德静态地图每张最多标注 10 个地点，因此更多坐标会自动分页，但侧栏仍会列出当前范围内的全部坐标点。

地图图像由主进程使用现有的高德 Web 服务 Key 请求，渲染页面只会得到有时效且数量受限的本地 `diary-map:` 图像地址，不会接触 Key。每次请求只发送当前页的 GCJ-02 经纬度，不发送日记正文、日期或文件名。静态地图使用方式及覆盖物限制以[高德静态地图官方文档](https://lbs.amap.com/api/webservice/guide/api/staticmaps/)为准。

纯 Markdown 旧库可以直接打开，不要求预先创建地点数据库。“洞察”会把只有地点文字、尚无坐标的记录标为待补全；点击“补全旧地点”后，应用按规范化后的原始地点文字分组，允许分别输入高德搜索词、可选城市 adcode，并把确认结果应用到全部同名记录、指定日期范围或单篇日记。原始地点文字与高德标准地点名分开保存，因此“家”“公司”等旧称无需改写。

旧地点扫描是只读的，打开迁移工具不会创建数据库。首次确认或跳过时才会创建 `.shiguang/locations.sqlite3`；每次批量确认前会在 `.shiguang/backups/` 生成一致性 SQLite 备份。迁移记录可按最近一次逐步撤销，跳过项可以恢复，迁移期间发生变化的日记会停止写入并要求重新扫描。已存在但与当前地点文字不匹配的坐标会列为冲突，不会被批量覆盖。

新建日记时可在“地点”中输入至少两个字，应用会通过高德输入提示服务列出地点、行政区和地址候选。点击“选择”后，地点名称仍写入原有的 `地点:` 字段，经纬度、坐标系和高德 POI 信息则保存到独立的本地 SQLite 数据库。阅读日记时点击带坐标的地点，应用会通过高德地图 URI 打开对应标记。

地点搜索需要在高德开放平台创建一个“Web 服务”Key，并在设置的“高德地点搜索”中保存。应用会检查 Electron 是否连接到真正的系统密钥服务，并通过 `safeStorage` 加密 Key；`basic_text` 不会被视为可用密钥服务，Key 也不会传给页面。

KDE Plasma 6 用户可以在“系统密钥环”中选择“KWallet 6”并重启应用。下次启动时应用会在 Electron 就绪前设置 `--password-store=kwallet6`，设置页面会显示实际选中的后端。切换密钥环前需要先清除已经加密保存的 Key，以免新后端无法解密旧数据。

也可以在启动应用时提供高德 Key 环境变量；环境变量优先于设置中加密保存的 Key。Linux shell：

```bash
SHIGUANG_AMAP_KEY='你的 Web 服务 Key' shiguang-diary
```

Windows PowerShell：

```powershell
$env:SHIGUANG_AMAP_KEY = '你的 Web 服务 Key'
npm start
```

时间轴针对数千篇日记进行了优化：启动阶段只扫描日期索引，正文按可见区域分批加载；页面仅渲染当前月份附近的小窗口，并在跨月时增量复用已有节点。桌面端图片通过受限本地协议流式读取和异步解码，避免大体积 Base64 阻塞滚动。

保留的浏览器开发模式可使用：

```bash
npm run start:web
```

## 存储约定

桌面应用只会读写用户明确选择的目录，文件严格采用以下结构：

```text
Diary/
├── .shiguang/
│   ├── analysis.sqlite3
│   ├── locations.sqlite3
│   └── backups/
│       └── locations-before-*.sqlite3
├── 0.media/
│   └── yyyy-mm-dd/
│       └── image.png
└── yyyy/
    └── yyyy-mm-dd.md
```

`.shiguang/analysis.sqlite3` 是可随时重建的本地派生索引，不保存日记原文。`.shiguang/locations.sqlite3` 保存用户确认的地点名称、高德 POI、GCJ-02 经纬度和坐标系；这些信息不会新增或改写 Frontmatter 字段。地点数据库不是派生索引，备份日记库时应一并保留。SQLite 的 WAL 临时文件可能在应用运行期间出现在同一目录中。

地点数据库同时保存原始地点文字的绑定、批量迁移批次、跳过项和撤销信息；`.shiguang/backups/` 中的迁移前备份也应随日记库保留。版本 1 地点数据库会在首次打开时原地升级并回填原始地点绑定，已有坐标不会丢失。

新日记会使用以下模板：

```markdown
---
时间: 2024-12-17 23:13
天气:
地点:
---
```

`时间` 会在创建日记时自动写入当前本地时间。

## Markdown 扩展

- 行内公式：`$E=mc^2$` 或 `\(E=mc^2\)`
- 块级公式：使用成对的 `$$` 或 `\[`、`\]`
- 本地图片：使用标准 `![说明](./images/photo.png)` 语法；图片必须位于 Diary 目录内
- 撰写窗口的“导入图片”按钮通过系统文件选择器选择图片（Linux 使用 XDG Desktop Portal），将文件复制到 `0.media/yyyy-mm-dd/`，并在光标处自动插入 `../0.media/yyyy-mm-dd/image.png` 形式的相对链接
- 图片会显示在气泡底部，最多展示三张缩略图，其余图片合并为 `+X`

支持 PNG、JPEG、GIF、WebP 和 AVIF，单张图片最大 12 MB。

应用会拒绝无效日期和不符合固定路径规则的请求；年份目录及日记文件必须符合约定命名。

## 操作

- 新建日记后会打开居中的 Gmail 风格撰写窗口，支持快捷插入标题、强调、列表、引用、代码、公式、链接和图片等 Markdown 元素，并自动保存；已有日记仍可在时间轴气泡中编辑。
- 在新建日记的地点框输入关键词，从高德候选中点击“选择”即可保存坐标；地点右侧的图钉或阅读气泡中的地点可在高德地图中查看。直接手动修改地点文字会清除该日记已关联的坐标，避免打开错误位置。
- 编辑内容后约 600 ms 自动保存，也可按 `Ctrl/⌘ + S` 立即保存。
- 按 `Ctrl/⌘ + K` 聚焦日记搜索。
- 在时间轴气泡右上角点击编辑，完成后回到阅读气泡。
- 点击图片缩略图打开浏览器；滚动鼠标滚轮可缩放，放大后按住鼠标左键可拖动查看图片，左右按钮或方向键可切换图片。
- 气泡右上角提供删除按钮，确认后会把 Markdown 文件移入当前日记库根目录的 `.Trash`；侧栏“回收”页面可查看、恢复、单篇永久删除或在二次确认后清空日记。同一天被多次回收时会保留独立版本，不会覆盖已有文件；永久删除只会处理应用管理的日期 Markdown 文件，不会删除 `.Trash` 中的其他文件。

## Windows 打包

在 Windows 10/11 x64 上安装依赖后，可同时生成 NSIS 安装程序和免安装便携版：

```powershell
npm install --include=dev
npm run build:win
```

在 Windows 上也可以直接运行 `npm run build`，平台分发脚本会自动选择 Windows 构建流程。

产物位于 `dist/`。若只需生成可直接运行的解包目录进行冒烟测试：

```powershell
npm run pack:win
```

Windows 包仅包含应用代码和静态资源，不包含仓库中的 `Diary`、`.shiguang` 或其他日记数据。正式分发前应为安装程序进行 Windows 代码签名。

## Arch Linux 打包

Arch 配方维护在 [AkiraLyu/pkgbuilds](https://github.com/AkiraLyu/pkgbuilds/tree/main/shiguang-diary)，从 GitHub 拉取本项目源码。配置好 Paru 后安装：

```bash
paru --sudo run0 -S shiguang-diary
shiguang-diary
```

`npm run build:arch` 会通过 Paru 重新构建并安装远端版本。包内安装应用代码、静态资源和 Wayland 背景模糊桥接库，运行时调用系统 Electron，不包含日记数据。构建自动运行项目测试。

运行测试：

```bash
npm test
```

测试围绕日记读写、搜索、图片、回收恢复、地点迁移和统计结果验证功能。网页接口测试使用工作区内的临时日记库和真实 HTTP 请求；Wayland 模糊测试检查实际协议消息。

测试不应通过读取源码、匹配函数名或调用写法、固定 CSS 数值来约束实现，也不应依赖随机洗牌的某一种排列或缓存的内部字段。原生窗口效果、系统目录选择器和不同平台的安装包需要在对应平台做冒烟验证。
