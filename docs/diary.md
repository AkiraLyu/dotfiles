# 拾光日记

[返回 README](../README.md)

拾光日记是面向 Windows 和 Linux 的本地 Markdown 日记应用，支持时间轴阅读、自动保存、全文搜索、图库、日历和本地统计。源码位于 [local/.local/src/diary](../local/.local/src/diary/)。

## 启动

开发环境需要 Node.js 24 或更高版本。项目依赖 Electron 43，文本洞察使用其内置 SQLite。Linux Wayland 环境还需要 C 编译器和 `wayland-scanner`，启动脚本会构建背景模糊桥接库。

从仓库根目录执行：

```bash
cd local/.local/src/diary
npm install --include=dev
npm start
```

本页后续的 `npm` 命令均在此源码目录执行。

启动后，通过“选择或创建目录”打开日记库。Linux 使用 XDG Desktop Portal 选择目录；Windows 支持输入尚不存在的路径，由应用创建目录。已有的纯 Markdown 日记库可以直接打开，无需预先创建数据库。

## 阅读与编辑

| 入口 | 功能 |
| --- | --- |
| 时间轴 | 按日期阅读和编辑日记，通过年份和年月导航定位记录 |
| 图库 | 按年月、日期浏览 Markdown 图片，支持缩放、拖动和同日图片切换 |
| 日历 | 查看各年的月度热力图；点击已有日期打开记录，点击空白日期创建日记 |
| 漫步 | 随机回顾旧日记，或查看日号相同、相隔完整月份的历史记录 |
| 洞察 | 按日期范围查看记录覆盖率、词数、连续记录、词频关联和地点统计 |
| 回收 | 恢复或永久删除已回收的日记 |

新建日记会打开撰写窗口，支持插入标题、强调、列表、引用、代码、公式、链接和图片。已有日记可通过时间轴气泡的编辑按钮修改。

| 操作 | 快捷键或入口 |
| --- | --- |
| 保存 | 停止编辑约 600 ms 后自动保存，或按 `Ctrl/⌘ + S` |
| 搜索 | `Ctrl/⌘ + K` 聚焦搜索框 |
| 查看图片 | 点击缩略图；滚轮缩放，放大后按住鼠标左键拖动 |
| 切换图片或回顾卡片 | 左右按钮或方向键；回顾卡片还支持触控滑动和触控板横向滚动 |
| 删除日记 | 点击气泡的删除按钮并确认，文件移入日记库的 `.Trash` |

同一天多次回收的日记保留独立版本。永久删除和清空只处理应用管理的日期 Markdown 文件，不删除 `.Trash` 中的其他文件。

### Markdown

- 行内公式使用 `$E=mc^2$` 或 `\(E=mc^2\)`。
- 块级公式使用成对的 `$$` 或 `\[`、`\]`。
- 图片使用标准 Markdown 语法，引用文件必须位于日记库内。
- “导入图片”将文件复制到 `0.media/yyyy-mm-dd/`，并插入 `../0.media/yyyy-mm-dd/image.png` 形式的相对链接。

支持 PNG、JPEG、GIF、WebP 和 AVIF，单张图片最大 12 MB。气泡底部最多显示三张缩略图，其余图片合并为数量入口。

## 设置与外观

设置面板提供缩放比例（80%–150%）、深色模式、背景透明度（0%–100%）、年月导航显示、日记目录、系统密钥环和高德 Web 服务 Key。

设置保存在 Electron 平台应用数据目录的 `config.json` 中。Linux 遵循 `$XDG_CONFIG_HOME`，Windows 使用当前用户的应用数据目录。应用还保存最近一次非最大化窗口的尺寸和最大化状态。

背景透明度只影响窗口背景，文字和图标保持不透明。背景模糊取决于系统支持：

| 平台 | 行为 |
| --- | --- |
| Windows | 保留原生窗口按钮；系统支持且透明度大于 0 时请求 Acrylic 模糊 |
| Linux Wayland | 合成器公布 `ext-background-effect-v1` 能力时请求模糊，强度由合成器决定 |
| X11 或不支持模糊的环境 | 保留透明背景 |

Linux Wayland 的桥接库仅在对应环境构建和加载。可用 `SHIGUANG_DISABLE_WAYLAND_BLUR=1` 禁用它，或用 `SHIGUANG_WAYLAND_BLUR_DEBUG=1` 输出协议协商信息。

## 地点

### 密钥配置

地点搜索需要高德开放平台的 Web 服务 Key。在设置中选择可用的系统密钥环，再保存 Key。应用通过 Electron `safeStorage` 加密密钥，Linux 的 `basic_text` 后端不视为可用密钥服务。

KDE Plasma 6 可选择 KWallet 6，重启应用后生效。切换密钥环前先清除已保存的 Key，再在新后端中重新保存，避免无法解密旧数据。

也可以通过环境变量提供 Key，其优先级高于设置中保存的值。Linux：

```bash
SHIGUANG_AMAP_KEY='你的 Web 服务 Key' npm start
```

Windows PowerShell：

```powershell
$env:SHIGUANG_AMAP_KEY = '你的 Web 服务 Key'
npm start
```

### 选择与查看

新建日记时，在地点框中输入至少两个字，从高德候选中选择地点。地点名称写入 `地点:` 字段，坐标、坐标系和 POI 信息保存在独立的 SQLite 数据库中。手动修改地点文字会清除原有坐标关联；点击已关联的地点可在高德地图中打开标记。

洞察页按日期范围展示地点填写率、常去地点、坐标确认率和行政区分布。已有坐标时，可打开地点地图查看名称、原始称呼、地址、坐标和记录次数。每页地图最多显示 10 个坐标点，侧栏列出范围内的全部坐标点。

地图图像由主进程请求，页面只接收有时效的本地 `diary-map:` 图像地址，不接收 Key。静态地图请求包含当前页的 GCJ-02 坐标，不包含日记正文、日期或文件名。

### 旧地点补全

“补全旧地点”按规范化后的原始地点文字分组。可为每组输入搜索词和可选的城市 adcode，再将结果应用到全部同名记录、指定日期范围或单篇日记。原始称呼与高德标准地点名分别保存，无需改写日记中的旧称。

扫描过程只读，首次确认或跳过时才创建地点数据库。每次批量确认前，应用在 `.shiguang/backups/` 生成一致性 SQLite 备份。迁移记录可逐批撤销，跳过项可以恢复；日记在迁移期间发生变化时，需要重新扫描。已有但与地点文字不匹配的坐标作为冲突处理，不会被批量覆盖。

## 存储与备份

日记文件使用 `yyyy/yyyy-mm-dd.md` 路径。应用拒绝无效日期和不符合该路径规则的请求。

```text
Diary/
├── .shiguang/
│   ├── analysis.sqlite3
│   ├── locations.sqlite3
│   └── backups/
│       └── locations-before-*.sqlite3
├── .Trash/
├── 0.media/
│   └── yyyy-mm-dd/
│       └── image.png
└── yyyy/
    └── yyyy-mm-dd.md
```

新日记使用以下 Frontmatter，`时间` 自动填写创建时的本地时间：

```markdown
---
时间: 2024-12-17 23:13
天气:
地点:
---
```

| 数据 | 用途 | 备份要求 |
| --- | --- | --- |
| 年份目录和 `0.media/` | 日记正文与图片 | 必须保留 |
| `.shiguang/locations.sqlite3` | 用户确认的坐标、原始地点绑定、迁移和撤销记录 | 必须保留，无法仅从正文重建 |
| `.shiguang/backups/` | 地点迁移前的数据库备份 | 随日记库保留 |
| `.Trash/` | 已回收的日记 | 需要保留恢复能力时一并备份 |
| `.shiguang/analysis.sqlite3` | 本地派生分析索引 | 可通过“重新建立分析索引”重建 |

备份前退出应用，并保留日记库内的隐藏目录。应用运行期间可能出现 SQLite WAL 文件。地点数据库的结构升级由应用处理，已有坐标及原始地点绑定保留。

洞察只读取正文、现有 `地点:` 字段和地点数据库，不改写日记或 Frontmatter；分析索引不保存日记原文。

## 开发

时间轴先扫描日期索引，再按可见区域载入正文。图库独立建立图片索引，洞察在后台建立本地分析索引。桌面图片通过本地协议读取，避免将全部图片转换为 Base64 后传入页面。

浏览器开发模式：

```bash
npm run start:web
```

默认访问地址为 `http://127.0.0.1:4173`，使用源码目录下的 `Diary/`。可通过 `HOST` 和 `PORT` 环境变量修改监听地址。此模式供网页界面开发使用，系统目录选择、密钥环和高德地点搜索等桌面能力由 Electron 提供。

## 构建与验证

### Windows

在 Windows 10/11 x64 上安装依赖后执行：

```powershell
npm run build:win
```

产物位于 `dist/`，包含 NSIS 安装程序和免安装便携版。`npm run build` 在 Windows 上选择相同构建流程；仅需可运行的解包目录时执行 `npm run pack:win`。

安装包只包含应用代码和静态资源，不包含日记库或地点数据库。正式分发前应完成 Windows 代码签名。

### Arch Linux

`npm run build:arch` 调用 `paru --sudo run0 -S --rebuild shiguang-diary`，依赖远端 PKGBUILD，不会打包当前工作区。

当前配置的 [pkgbuilds 仓库](https://github.com/AkiraLyu/pkgbuilds)未提供 `shiguang-diary` 配方；开发和本机使用请按[启动](#启动)一节运行。配方发布并配置到 Paru 后，才能使用该打包命令。

### 验证

```bash
npm test
```

测试覆盖日记读写、搜索、图片、回收恢复、地点迁移和统计结果。网页接口测试使用临时日记库和真实 HTTP 请求，Wayland 测试检查协议交互。

回归测试应验证可观察行为，避免通过读取源码、固定函数名或 CSS 数值约束实现，也不依赖随机洗牌结果和缓存内部结构。原生窗口效果、系统目录选择器及安装包需在目标平台验证。
